# 动画迁移实测 · 2026-09-07

旧界面的 `after(16)` 在绘制回调结束后再等待，既不与显示器垂直同步，也有额外调度延迟。真实 Tk mainloop 下，进入设置的回调间隔中位数 19.833 ms，悬停 29.504 ms；换色同步占用主线程的中位数为 28.759 ms。

新入口使用 PySide6 6.11.2 + Qt Quick，指定 threaded render loop、请求 swap interval 1。两页固定放在同一个容器中，只对容器使用一个 XAnimator；悬停使用 OpacityAnimator，按压使用 ScaleAnimator。不再由 Python 定时器推进动画。Python 的 100 ms 定时器只处理后台事件和日志。

## 导航白屏修复

早期帧信号测量遗漏了实际画面正确性：原来的两个独立 XAnimator 在同一个 Transition 中执行，进入中途画面不移动，返回后主页仍停在窗口外。只移除 reversible 或保持页面可见均未修复；两个色块的最小复现也有相同问题。改成单容器的 Behavior on x 后，进入、返回均能看到连续移动的中间画面。

新增 `test_qt_navigation.py`，真实点击设置和返回按钮，检查中途像素差、空白帧和目的页图像。旧实现明确失败，修复后在 0.5×、1×、2×、快速反向切换及减少动态下通过。下表导航行是修复后重新测量的结果；其余为前次控件测量。图形界面中的刷新率说明已移除，自动适配保留。

屏幕信息来自窗口的 QScreen，监听窗口换屏和 refreshRateChanged。没有固定 FPS 上限或刷新率白名单，速度设置只改变动画持续时间。信号回归覆盖 59.94、60、75、90、120、144、160、165、240、360、500 Hz 和换屏后旧信号解绑；这是逻辑测试，不能代替这些屏幕的硬件实测。

## 本机结果

Windows 11，Direct3D 11，160 Hz，150% 缩放，940 × 900 逻辑像素。160 Hz 每帧预算为 6.25 ms。

| 动画 | 样本数 | 帧交换间隔中位数 | p95 | 最大值 | 超过 9.375 ms |
| --- | ---: | ---: | ---: | ---: | ---: |
| 进入设置 | 284 | 6.246 ms | 6.370 ms | 6.474 ms | 0% |
| 返回首页 | 285 | 6.245 ms | 6.389 ms | 6.541 ms | 0% |
| 悬停 | 348 | 6.250 ms | 6.409 ms | 7.104 ms | 0% |
| 按压 | 249 | 6.247 ms | 6.426 ms | 7.015 ms | 0% |
| 换色 | 756 | 6.243 ms | 9.060 ms | 9.894 ms | 1.46% |

使用 Qt.DirectConnection，在独立渲染信号线程记录 frameSwapped 的 perf_counter 时间。只统计动画开始 50 ms 后至结束前 30 ms 的稳定区间，排除空闲和启动边界。悬停通过 Qt HoverEnter/HoverLeave 事件触发并断言 hovered；按压修改 down，不调用穿透操作。

这些数据表示应用的帧交换节奏，不是物理屏幕扫描输出的 FPS；不是对每一帧无掉帧的保证。换色仍有少量较长间隔。多屏不同刷新率、VRR、其他显卡和刷新率尚未硬件实测。Qt 的同步能力也取决于平台和驱动提供的垂直同步行为，见 [Qt Quick 官方渲染说明](https://doc.qt.io/qt-6/qtquick-visualcanvas-scenegraph.html)。
